매일 채용 사이트 여러 곳을 열어 보는 일이 귀찮아서, 조건에 맞는 공고만 아침에 알려 주는 봇을 만들었습니다. 결과는 이렇습니다.

- 매일 아침 8시(한국 시간)에 자동으로 실행됩니다.
- 조건에 맞는 공고가 있을 때만 텔레그램으로 알림이 옵니다. 없으면 아무것도 오지 않습니다.
- 알림에는 판단 근거와 회사의 매출·영업이익률이 같이 붙습니다.
- 비용은 0원입니다. AI API를 쓰지 않습니다.

이 글에서는 구조, 사이트별로 수집하는 방법, 비용 때문에 중간에 방향을 바꾼 이유, 알림에 회사 재무 정보를 붙이는 방법을 정리합니다. 알림 받은 공고를 구글 시트에 쌓아서 지원 현황을 관리하는 방법은 [[AI-Projects/job-alert/2-sheets|다음 글]]에 따로 썼습니다.

## 전체 구조

| 단계 | 하는 일 | 도구 |
|---|---|---|
| 실행 주기 | 매일 08:00(KST) 실행 | GitHub Actions 스케줄 |
| 수집 | 채용 사이트 여러 곳에서 공고 목록 가져오기 | Python, requests, BeautifulSoup |
| 정리 | 같은 공고 중복 제거, 제목·연차 기준으로 먼저 거르기 | Python |
| 채점 | 직무, 직급, 회사 규모, 연봉으로 점수 매기기 | 규칙 기반 (키워드) |
| 재무 | 알림 대상 회사의 매출·영업이익률 조회 | DART 오픈API |
| 기록 | 조건 통과 공고를 노트로 저장하고, 본 공고 목록 보관 | Markdown, JSON |
| 알림 | 조건 통과 공고를 텔레그램으로 발송 | 텔레그램 봇 API |

저장소는 비공개로 두고, 결과 노트는 같은 저장소에 커밋되게 했습니다. 그래서 옵시디언 볼트 폴더에서 `git pull`만 하면 노트가 들어옵니다.

## 1. 처음 계획: AI가 채점하게 하기

처음에는 Claude API에 공고를 넘겨서 점수를 매기게 할 계획이었습니다. 공고마다 "이 사람에게 맞는가"를 읽고 판단하면 가장 정확할 거라고 생각했습니다.

그런데 API는 쓴 만큼 돈을 내는 방식입니다. 공고가 하루 수백 건씩 들어오니, 최소한 몇 달러는 매달 나갈 수 있습니다. 무료로 쓰는 게 목표였기 때문에 방향을 바꿨습니다.

방향을 바꾸면서 생긴 트레이드오프는 분명합니다.

- **장점:** 비용이 0원이고, 키 관리도 필요 없습니다.
- **단점:** 공고 문장을 이해하지 못합니다. 키워드가 맞지 않으면 놓치거나 엉뚱한 공고가 옵니다.

결국 "정확한 판단"을 조금 포기하고, 대신 **판단 근거를 알림에 같이 적는 방식**을 택했습니다. 점수만 보내는 대신 "직무 키워드 제목에서 확인 · 직급 확인 · 연봉 미공개, 직접 확인"처럼 이유를 함께 보내서, 최종 판단은 사람이 하도록 했습니다.

## 2. 사이트별 수집: 막힌 곳과 열린 곳

채용 사이트마다 공고를 가져오는 방법이 달랐습니다. 먼저 사이트별로 접근해 본 결과는 다음과 같습니다.

| 사이트  | 방법                       | 결과                                |
| ---- | ------------------------ | --------------------------------- |
| 원티드  | 공개 API (목록, 검색, 상세)      | 내 PC에서는 동작, GitHub 서버에서는 403으로 막힘 |
| 리멤버  | 검색용 API (POST)           | 잘 동작                              |
| 사람인  | 검색 결과 HTML               | 잘 동작                              |
| 잡코리아 | 검색 결과 HTML (React 화면)    | 잘 동작 (카드 구조 분석 필요)                |
| 인크루트 | 검색 결과 HTML (cp949 인코딩)   | 잘 동작                              |
| 링크드인 | 로그인 없이 보는 공개 검색 API      | 잘 동작                              |
| 인디드  | 접속 자체를 차단                | 403, 제외                           |
| 캐치   | 결과를 자바스크립트로 그려서 HTML에 없음 | 제외                                |
| 커리어  | 결과를 별도 요청으로 불러오고 로그인 유도  | 제외                                |

여기서 배운 점은 **브라우저에서 보이는 화면과, 실제로 데이터가 오는 요청은 다르다**는 것입니다. 개발자 도구의 네트워크 탭을 열어 보면, 화면에 없는 JSON API가 보이는 경우가 많습니다. 리멤버는 바로 그 방식으로 찾았습니다.

## 3. 같은 공고, 여러 사이트

같은 회사가 같은 공고를 여러 사이트에 올리는 경우가 많았습니다. 이걸 그대로 두면 알림이 중복으로 옵니다.

그래서 회사명과 제목에서 괄호, `(주)`, 공백, 특수문자를 지운 뒤 소문자로 맞춰서 비교했습니다. 같은 키가 나오면 중복으로 보고, 본문이 더 풍부한 사이트의 공고를 남겼습니다.

## 4. 규칙으로 채점하기

채점은 공고 정보를 몇 가지 항목으로 나눠 키워드를 찾고, 항목별 점수를 더하는 방식입니다.

- **직무 일치(40점):** 제목과 본문에서 핵심 직무 키워드를 찾습니다. 제목에 있으면 본문에만 있을 때보다 높게 봅니다. 그로스, 퍼포먼스, 마테크 같은 연관 단어가 함께 있으면 점수를 더합니다.
- **경력 연차(30점):** 공고에 적힌 요구 연차가 내 경력 범위와 맞는지 봅니다.
- **직급(15점):** 공고 제목의 직급 표현으로 판단합니다. 실무자 직급과 리더급 직급을 구분하고, 직급이 드러나지 않으면 불명으로 둡니다.
- **회사(15점):** 회사 규모와 상장 여부 같은 정보를 키워드로 추정합니다.

여기에 **직무 관련성 상한**을 하나 더 뒀습니다. 제목에 직무 키워드가 없고 본문에도 거의 안 나오면, 다른 항목이 아무리 높아도 45점을 넘지 못하게 막습니다. 이 장치가 없으면 직무가 전혀 안 맞아도 "리더급 + 경력 일치 + 큰 회사"만으로 합격선인 60점을 넘습니다. 백엔드 개발자나 컴플라이언스 공고가 알림으로 왔던 이유가 이것이었습니다. 제목에 브랜드, 개발, 영업 같은 단어가 들어가면 아예 제외하는 목록도 함께 뒀습니다.

연봉은 공고에 금액이 적혀 있을 때만 확인합니다. 적혀 있지 않으면 "미공개, 직접 확인"으로 표시하고 알림은 보냅니다. 이렇게 하지 않으면 대부분의 공고가 빠져 버리기 때문입니다.

## 5. GitHub Actions로 매일 아침 실행하기

GitHub Actions는 정해진 시간에 서버에서 코드를 실행해 줍니다. 컴퓨터를 켜 두지 않아도 됩니다.

- **cron 설정:** GitHub의 시간은 UTC입니다. 한국 시간 08:00은 UTC 23:00이므로 `0 23 * * *`로 적었습니다.
- **수동 실행:** `workflow_dispatch`를 넣어서 버튼으로도 실행할 수 있게 했습니다. 이때 `dry_run` 체크박스를 두면, 수집만 하고 채점과 알림은 건너뜁니다. 처음 테스트할 때 이 옵션이 특히 쓸모 있었습니다.
- **결과 커밋:** 실행이 끝나면 본 공고 목록과 노트를 저장소에 커밋합니다.

## 6. 텔레그램 알림 설정

텔레그램 봇을 만드는 데는 세 단계가 필요합니다.

1. **@BotFather**에게 `/newbot`을 보내서 봇을 만들고, 받은 토큰을 저장합니다.
2. 만든 봇에게 `/start`를 한 번 보냅니다. 이걸 빼먹으면 봇이 나에게 메시지를 보낼 수 없습니다.
3. **@userinfobot**에게 `/start`를 보내면 내 ID가 나옵니다. 개인 채팅이라면 이 숫자가 Chat ID입니다.

토큰과 Chat ID는 GitHub 저장소의 **Secrets**에 넣습니다. 코드나 공개된 곳에는 절대 적지 않습니다. 토큰은 `숫자:영문과 숫자가 섞인 긴 문자열` 형태라서, 콜론 뒤까지 전부 복사해야 합니다.

## 7. 알림에 회사 매출·영업이익률 붙이기

알림에 오는 회사 중에는 처음 들어 보는 곳이 많았습니다. 그래서 알림마다 회사의 최근 매출과 영업이익률을 같이 보내게 했습니다.

금융감독원 전자공시(DART)의 오픈API를 썼습니다. opendart.fss.or.kr에서 이메일로 무료 키를 바로 받을 수 있습니다.

1. 회사 이름으로 DART의 법인 코드를 찾습니다.
2. 법인 코드로 최근 사업연도의 매출액과 영업이익을 가져옵니다.
3. 영업이익을 매출액으로 나눠 영업이익률을 계산하고, `매출 ○○억 · 영업이익률 ○%` 형태로 알림에 붙입니다.

몇 가지 손볼 점이 있었습니다.

- 공고의 회사명은 `(주)`가 앞뒤로 붙거나 영문 약칭으로 적혀 있는데, DART에는 한글로 등록된 경우가 많습니다. `(주)`를 지우고, 영문 약칭을 한글로 바꿔 보는 변환표를 뒀습니다.
- 같은 이름의 법인이 여럿이면 후보를 모두 조회해서 재무 정보가 있는 쪽을 씁니다.
- 조회한 결과는 일정 기간 저장해 두고 다시 쓰고, 못 찾은 결과는 며칠만 저장합니다.

한계도 있습니다. 이 API는 사업보고서를 내는 회사, 즉 주로 상장사의 숫자만 줍니다. 큰 기업의 계열사여도 비상장이면 비어 있는 경우가 있었습니다. 이럴 때는 억지로 채우지 않고 "재무 정보 없음"으로 표시합니다. 틀린 숫자보다 빈칸이 낫다고 판단했습니다.

## 실제로 겪은 문제들

### 문제 1: 점수 기준을 낮춰도 알림이 계속 0건

알림이 안 와서 합격선을 70점에서 65점, 60점으로 낮췄는데도 계속 `알림 대상 0건`이었습니다. 점수가 문제가 아니었습니다.

- **진짜 원인:** 사람인, 잡코리아 같은 목록 화면에는 회사 정보가 거의 없습니다. 그래서 회사 규모를 "불명"으로 판정한 공고가 약 90%였고, 설정에서 불명을 제외하고 있었습니다. 점수가 높아도 이 조건에서 먼저 탈락했습니다.
- **함께 겹친 문제:** 한 번 채점한 공고는 "본 공고"로 저장하고 다시 채점하지 않습니다. 기준을 바꿔도 이미 본 공고는 다시 평가되지 않았습니다.
- **해결:** 회사 규모 불명도 알림에 포함하되 "회사 규모 불명, 확인"을 붙였습니다. 기준을 바꾼 뒤에는 저장된 공고 목록에서 새 기준에 맞을 공고를 풀어 줬습니다.

알림이 안 올 때는 합격선만 만지지 말고, **조건별로 몇 건이 탈락했는지 먼저 세어 보세요.** 점수 말고 다른 필터가 조용히 걸러 내고 있을 수 있습니다.

### 문제 2: "Re-run"은 예전 설정으로 다시 실행된다

수동 실행을 테스트하다가 결과가 이상해서 "Re-run all jobs"를 눌렀습니다. 그런데 재실행은 처음 실행했을 때의 커밋과 입력값을 그대로 씁니다. 그 뒤에 워크플로우 파일이나 설정을 고쳐 푸시했어도 반영되지 않고, 켜 둔 `dry_run`도 그대로 남습니다. 새 설정으로 돌리려면 **Run workflow**를 눌러서 입력값을 다시 고르세요.

## 정리

- 비용이 드는 AI 대신 규칙 기반 채점을 택했습니다. 정확도는 떨어지지만 비용은 0원입니다.
- 사이트마다 방법이 달랐습니다. 화면에 안 보이는 API를 찾는 것이 핵심이었습니다.
- 한 번 막혔다고 판단한 사이트도 나중에 다시 시도해 볼 만합니다.
- 알림에 판단 근거와 회사 재무 정보를 함께 적으면, 점수가 틀려도 사람이 빠르게 걸러낼 수 있습니다.
